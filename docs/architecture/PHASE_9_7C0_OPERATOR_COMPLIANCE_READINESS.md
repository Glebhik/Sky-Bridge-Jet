# Phase 9.7.C0 — Operator-safe compliance readiness

Phase 9.7.C0 is based on `540d29d800de340d557effd29ee00687a53b4b96`. It adds one authenticated read, `GET /api/v1/me/operator-compliance-readiness`, so Phase 9.7.C can present the marketplace readiness of the operator represented by the selected active OPERATOR organization without accepting an operator selector.

The route derives the operator from the authenticated principal, validated active organization membership, and `active_operator_id`; all five operator roles read through `operator.read`. It grants no evidence submission or platform review authority.

The dedicated response contains only admission status, canonical marketplace eligibility, safe canonical blocker codes, and admission creation/update timestamps. Admission status and marketplace eligibility remain distinct. No combined expiry is emitted because the canonical evaluator defines current evidence validity but no single operator-level effective-expiry value. The response excludes operator identifiers, review reasons or notes, reviewer identity, audit data, raw evidence, document/storage references, aircraft, customer/passenger data, and payment/provider data.

Marketplace eligibility is produced only by the existing `ComplianceEvaluator`. Its repository obtains the two facts needed for each required evidence type—whether current VERIFIED evidence exists and whether expired VERIFIED evidence exists—through one bounded scalar `EXISTS` query. It never transfers or materializes evidence history, while preserving canonical missing-versus-expired reasons with mixed current, expired, and unverified rows. A durable 1,202-row regression verifies the fixed five-query shape and zero `ComplianceEvidence` ORM loads. The read makes no business mutation. Aircraft readiness remains exclusively `GET /api/v1/me/operator-aircraft`; evidence reads/submission, document handling, and all platform review actions remain deferred and closed to the Phase 9.7.C Web proxy.

The route is authenticated and explicitly classified in route policy. Inventory becomes 93 registered / 89 OpenAPI operations / 4 documentation routes. Alembic remains `20260827_0010`; there is no migration, Web change, dependency, or lockfile change. Phase 9.7.C may resume as a read-only UI using this operator projection plus the existing aircraft collection, with the proven organization-epoch model and no polling or N+1 reads.
